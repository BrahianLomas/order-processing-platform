## Entities

### `Customer` (`customers` table)

| Field | Type | Notes |
|---|---|---|
| `id` | `Long` | PK, `IDENTITY` |
| `firstName`, `lastName` | `String` | not null |
| `email` | `String` | unique, not null |
| `phone` | `String` | unique, not null |
| `address`, `city`, `state`, `zipCode` | `String` | not null |
| `createdAt` | `LocalDateTime` | `@PrePersist` |

### `CarSale` (`car_sales` table)

| Field | Type | Notes |
|---|---|---|
| `id` | `Long` | PK, `IDENTITY` |
| `customer` | `Customer` | `@ManyToOne(LAZY)`, `customer_id` not null |
| `vehicleVin`, `vehicleMake`, `vehicleModel`, `vehicleColor` | `String` | |
| `vehicleYear` | `Integer` | |
| `vehicleMileage` | `Long` | |
| `salePrice`, `discount`, `tax`, `totalAmount` | `BigDecimal` | not null |
| `status` | `String` | `PENDING` (default) → `PAID` / `COMPLETED` / `CANCELLED` |
| `createdAt` / `updatedAt` | `LocalDateTime` | `@PrePersist`/`@PreUpdate` |

## Business logic — pricing calculation

```text
tax          = (salePrice - discount) * 0.08
totalAmount  = salePrice - discount + tax
```

## Endpoints

Full examples in [[../04-API-Reference/02-Sales-Endpoints|API Reference: Sales]].

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/sales` | Creates a sale, computes pricing, publishes `CarSaleCreatedEvent` |
| `GET` | `/api/sales/{saleId}` | Fetches a sale by ID |
| `GET` | `/api/sales/customer/{customerId}` | Lists a customer's sales |
| `DELETE` | `/api/sales/{saleId}` | "Soft" cancellation (`status=CANCELLED`); fails if already `PAID` |

## 🔐 Security

`order-service` validates the JWT issued by `api-gateway` (same `app.jwt.secret`, HS256). Every `/sales/**` endpoint requires a valid token:

```java
.authorizeHttpRequests(authorize -> authorize
    .anyRequest().authenticated()
)
.addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
```

- No `Authorization: Bearer <token>` header, or an invalid/expired token → `401 Unauthorized` with a `GenericResponse` body (`response_code: E004`), generated by `RestAuthenticationEntryPoint` — never reaches the controller. See [[../04-API-Reference/00-Response-Format|Response Format]].
- A valid token → the request proceeds normally into `CarSaleController`
- Verified live: `POST /auth/login` on `api-gateway` → `GET /sales/{id}` on `order-service` with the resulting token

> [!note] Same pattern as `api-gateway`
> `JwtConfig`, `SecurityConfig`, `JwtAuthenticationFilter` and `RestAuthenticationEntryPoint` are a deliberate copy of `api-gateway`'s (see [[01-API-Gateway|API Gateway]]), reusing `JwtUtil` from `shared-lib`. It wasn't extracted into `shared-lib` to avoid coupling that module to Spring Security — see [[../01-Architecture/04-Design-Decisions|Design Decisions]].

## 📖 Swagger UI

Public, no authentication: **`http://localhost:8081/api/swagger-ui/index.html`**. Unlike `api-gateway`, this one has an **Authorize** button (a `bearerAuth` scheme defined in `OpenApiConfig`) — paste the JWT obtained from `/auth/login` to try `POST/GET/DELETE /sales/*` directly from the browser.

## Kafka — Producer

`CarSaleEventProducer.publishCarSaleCreated(CarSaleCreatedEvent event)` publishes to the **`car-sale-created`** topic using `KafkaTemplate<String, CarSaleCreatedEvent>` (key: `StringSerializer`, value: `JsonSerializer`).

> [!note] Mapping detail (`CarSaleMapper`)
> The event's `sale_price` field is populated from `CarSale.totalAmount`, **not** the raw `salePrice`. In other words, the event carries the final amount to be charged. See [[../05-Kafka-Events/02-CarSaleCreatedEvent|CarSaleCreatedEvent]].
