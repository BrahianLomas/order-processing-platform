# 💳 Payment Endpoints

Base URL: `http://localhost:8082/api`

> [!note] Single, read-only endpoint
> `payment-service` exposes no way to create payments via REST. Payments are only generated by consuming `CarSaleCreatedEvent` from Kafka — see [[../03-Services/03-Payment-Service|Payment Service]].

> [!tip] Requires authentication
> Requires a valid `Authorization: Bearer <token>` header (issued by `api-gateway`). Without it → `401 Unauthorized`.

> [!info] Response format
> Every response follows the homologated `GenericResponse` envelope — see [[00-Response-Format|Response Format]].

## GET `/payments/sales/{saleId}`

Fetches the payment associated with a sale.

**Response — `200 OK`**
```json
{
  "id": 7,
  "saleId": 10,
  "amount": 26460.00,
  "currency": "usd",
  "status": "PAID",
  "transactionId": "pi_3Nx...",
  "createdAt": "2026-09-03T10:15:03",
  "response_code": "00",
  "description": "Successful",
  "timestamp": "2026-09-12T09:15:31.594"
}
```

**Response — `404 Not Found`**
```json
{
  "response_code": "E006",
  "description": "Pago no encontrado",
  "timestamp": "2026-09-12T09:15:31.594"
}
```
> Thrown internally as `PaymentException("PAYMENT_NOT_FOUND", ...)`.

## Notes on payment status

- `status = "PAID"` **does not mean Stripe confirmed the charge** — it's a value the service sets in a simulated way right after creating the `PaymentIntent` (test mode). See the warning in [[../03-Services/03-Payment-Service|Payment Service]].
- `transactionId` corresponds to the Stripe `PaymentIntent`'s `id`.
- `amount` is stored in normal currency units (e.g. dollars), even though Stripe internally works in cents.
